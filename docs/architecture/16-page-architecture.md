# 16 - 页面信息架构（Page Architecture）

> BTC 全市场智能研究平台 · 前端信息架构设计
>
> 技术栈：Next.js 15 (App Router) + React 19 + TypeScript + Tailwind CSS + ECharts / TradingView Lightweight Charts

---

## 概述

本文档定义平台全部 25 个页面的导航结构、布局层级、组件划分与交互模式。核心设计原则来自需求文档：

1. **普通用户优先**：默认展示描述性结论（如「市场估值：偏高」），不堆砌专业术语；
2. **一路可追溯**：任何结论都能通过「为什么？」逐层展开到原始数据、数据源与时间戳；
3. **双模式切换**：全局「普通模式 / 专业模式」开关，且每个组件支持局部切换；
4. **局部故障不扩散**：某类数据不可用时，对应卡片显示「数据暂时不可用 + 最后更新时间」，页面其余部分正常；
5. **绝不显示假数据**：Provider 未配置/未连接时明确提示，不伪造数字。

## 2. 全局布局框架

所有页面共享统一 Shell：

```text
┌─────────────────────────────────────────────────────┐
│ TopBar (56px)                                       │
├────────┬────────────────────────────────────────────┤
│        │ PageHeader: 标题 + 一句话说明 + 数据时效标签   │
│ Side   ├────────────────────────────────────────────┤
│ bar    │ Breadcrumb / 页内 Tab（如有）                │
│(220px) ├────────────────────────────────────────────┤
│        │                                            │
│        │ PageBody (max-width 1440px, 响应式栅格)      │
│        │                                            │
├────────┴────────────────────────────────────────────┤
│ Footer: 数据免责声明 + 数据源清单 + 最后同步时间          │
└─────────────────────────────────────────────────────┘
```

**每个 PageHeader 必须包含**：

- 页面标题与「这个页面回答什么问题」的一句话说明（普通模式友好）；
- 数据时效标签：`实时` / `5分钟延迟` / `日更` / `数据暂不可用（最后更新 XX）`；
- 页面级「为什么？」入口（展开本页结论的完整证据链）。

## 4. 普通用户模式 vs 专业模式

（参考需求文档第二十八节）

### 4.1 模式定义

| 维度 | 普通模式（默认） | 专业模式 |
|------|----------------|---------|
| 展示内容 | 描述性结论 + 状态色 + 一句话解释 | 全部原始信息 |
| 数字表达 | 「估值：偏高」「资金：净流入」 | MVRV=2.38、Z-Score=2.1、分位 78% |
| 图表 | 简化曲线 + 区间色带 | 多轴、原始序列、标准化序列叠加 |
| 术语 | 中文描述，术语附 tooltip | 直接使用术语 |
| 公式 | 隐藏 | 展示数学定义与计算过程 |
| 模型 | 只给结论与置信度 | 权重、版本、样本区间、验证结果 |
| 数据源 | 只显示「数据来源: XXX」标记 | Provider 全链路：请求参数、原始响应、抓取时间、质量状态 |

### 4.2 普通模式点击展开的内容

普通模式下用户点击任意结论卡片，展开以下信息（仍为通俗表达）：

- 关键数值（MVRV=2.38，配「这是什么」tooltip）；
- 历史分位（「比过去 78% 的时间都高」）；
- 数据来源与更新时间；
- **为什么重要**（该指标解释了什么市场行为）；
- **历史通常代表什么**（历史相似状态及后续表现，附免责声明）;
- **当前支持证据 / 反对证据** 列表。

### 4.3 专业模式额外内容

- 指标公式与数学定义（LaTeX 渲染）；
- 原始数值 + 标准化数值（Z-Score / 分位 / 归一化）双列展示；
- 模型权重表、模型版本号、训练/测试区间、Walk-Forward 结果；
- 完整计算过程（输入序列 → 中间步骤 → 输出）；
- Provider 原始响应 JSON 查看器；
- 数据表下载（CSV）。

### 4.4 切换机制

| 层级 | 方式 | 持久化 |
|------|------|--------|
| 全局 | 顶部工具栏「普通/专业」开关 | 用户配置（登录用户存后端，匿名存 localStorage） |
| 组件局部 | 每个卡片/图表右上角 `[普通|专业]` 小切换钮 | 组件级 state，不覆盖全局设置 |

规则：局部切换优先于全局；组件未局部切换时继承全局模式。全局切到专业模式时，所有组件强制专业展示。

## 5. 统一三级信息层级

全站所有数据组件遵循同一套三级展开模式，保证任何页面的学习成本一致：

### Level 1 —— 摘要（默认可见）

- **一句话结论** + **状态颜色**（绿/黄/红/灰）+ **置信度**（如有）；
- 例：`估值：偏高 🟡 置信度 82%`；
- 附加：数据时效角标（`3秒前` / `数据暂不可用`）。

### Level 2 —— 展开（点击卡片）

- 关键数据列表（指标名、当前值、历史分位、变化方向）；
- 支持/反对证据；
- 历史相似阶段对比（含后续实际走势与免责提示）；
- 简化图表（近 1 年走势 + 当前值标注）。

### Level 3 —— 详情/原始（点击「详情」或专业模式内点击）

- 原始数据序列（可翻页、可导出 CSV）；
- 完整计算过程与公式；
- 数据源明细：Provider 名称、API Endpoint、请求参数、抓取时间、observation_time、quality_status、原始响应 JSON；
- 历史修订记录（宏观数据的 revision 链）；
- 时间戳与模型版本。

**组件实现约定**：前端封装 `<InsightCard level1 level2 level3 />` 通用组件，所有页面复用，展开动画、状态色、溯源标记行为全站一致。

## 6. 数据溯源 UI

（对应需求「所有数据都能够追溯」「每个关键数据都有来源」）

### 6.1 来源标记

任何来自外部或计算的数字旁显示小型来源徽标：

```text
MVRV = 2.38 [G]        ← 绿色小圆标: VERIFIED
BTC = $108,240 [B] ⚠   ← 黄色: STALE（数据过期）
ETF净流入 = $320M [F] ⛔ ← 红色: CONFLICT（多源冲突）
```

### 6.2 来源弹窗（点击徽标）

```text
┌─ 数据来源 ────────────────────────────┐
│ Provider:   Glassnode (备用源)         │
│ 原主数据源: CryptoQuant (Timeout 切换)  │
│ 状态:       ⚠ STALE                   │
│ 数据时间:   2026-09-27 00:00 UTC       │
│ 抓取时间:   2026-09-27 06:12:33 UTC    │
│ 交叉验证:   2/3 源一致，偏差 0.3%        │
│ [专业模式] API Endpoint / 原始响应 JSON  │
│ [查看该 Provider 健康详情]              │
└───────────────────────────────────────┘
```

### 6.3 数据异常视觉提示

| 质量状态 | 视觉 | 用户可见文案 |
|---------|------|-------------|
| VERIFIED | 无额外提示（徽标绿色） | — |
| ESTIMATED | 蓝色虚线下划线 | 「估算值，基于 XX 推算」 |
| STALE | 黄色警告条 + 徽标黄色 | 「数据暂时无法更新，最后成功更新：XX:XX」 |
| CONFLICT | 红色徽标 + 卡片顶部红色横条 | 「数据源存在异常差异，当前结果仅供参考」 |
| INVALID | 灰色占位 | 「数据校验失败 / 数据源未配置 / 当前 Provider 未连接」 |

规则（需求第十一、十四条）：STALE 时**继续显示最近一次可信数据**，绝不清空为 ERROR，绝不伪造数字。

## 7. 状态颜色与视觉语言

| 语义 | 颜色 | 适用 |
|------|------|------|
| 积极/安全/看多证据 | 绿 `--color-positive` | 低估、净流入、风险低、Provider ONLINE |

注意：涨/跌颜色遵循中国用户习惯可配置（默认绿涨红跌，可切换国际惯例红涨绿跌）。

### 8.3 市场周期（Cycle）`/cycle`

### 8.13 历史回放（Time Machine）`/time-machine`

- **目的**：回到任意历史日期，以「当时视角」或「事后视角」查看系统会如何判断。
- **核心组件**：
  1. 日期选择器 + 时间轴滑块（2015 至今，含数据覆盖范围提示）；
  2. 视角切换：`当时视角`（严格只显示该日期前已知信息，禁止未来泄漏）/ `事后视角`（显示之后 30/90/180/365 天实际走势）；
  3. 当日全景快照：还原首页 9 维度卡片（使用历史引擎输出）；
  4. 当日价格 + 指标 + 链上 + 资金 + 衍生品 + 宏观 + 情绪完整数据面板；
  5. 「如果当时定投」快捷入口：以该日期为起点跳转定投模拟；
  6. 事件标注：当日发生的市场事件。
- **数据来源**：`GET /engine/history?date=YYYY-MM-DD`、各数据模块的历史查询端点（均带 `as_of` 参数）。
- **交互**：日期切换 → 全页数据联动刷新；播放模式（按日/周自动前进，观察状态演变）；快照分享链接（URL 带日期参数）。
- **普通模式**：当日结论卡片（和首页一致的表达）+ 事后视角的「后来发生了什么」通俗总结。
- **专业模式**：当日全部原始数据表、当时使用的模型版本、宏观数据 observation vs release 日期标注、数据可用性说明（某些数据在该历史日期缺失时明确标记 INVALID）。
- **重要规则**：当时视角下，若某引擎在该历史日期无输出，显示「该日期系统尚无判断记录」，不回补伪造。

## 10. 降级与异常页面状态

（需求第十一、四十四节：局部故障不影响整体）

| 场景 | 页面行为 |
|------|---------|
| 单指标 Provider 全挂 | 该卡片显示最近可信值 + STALE 黄条 +「最后成功更新 XX」；其余卡片正常 |
| 某数据类别全挂（如链上） | 对应页面顶部横幅「链上数据暂时不可用」，页面展示本地历史数据；首页对应卡片置灰显示「数据暂不可用」 |
| 全部实时源挂 | 全站顶部红色横幅；所有页面自动切「历史模式」（读本地库）；个人计划/资产/回测/历史回放完全不受影响 |
| WebSocket 断开 | 自动重连（指数退避）；期间价格显示轮询兜底 + 「实时更新已暂停」提示 |
| 后端完全不可达 | 前端显示友好错误页 + 最近一次缓存快照（如有）+ 重试按钮 |
| Provider 未配置 | 对应区块显示「数据源未配置」引导（Admin 可见配置入口），绝不显示假数据 |

所有降级状态组件统一使用 `<DegradedNotice status lastUpdate />`，保证提示风格全站一致。
